# XingTu Visual Storytelling｜可复用的技术长文视觉结构（Draft）

## 目标与原理

本规范适用于架构解读、工程实践、产品白皮书、技术资讯四类内容，不是要求四类文章套一套僵硬模板。

1. **外化工作记忆**：把读者要自己记住的关系（状态、时序、依赖）画在外部，使前后步骤可对照；不是把段落贴到图片。
2. **渐进披露**：复杂图先展示起点，再揭示决策和结果；静态连续分镜比强行做动图更可靠。
3. **双通道互补**：正文讲动机、证据与例外；图承担路径、状态、结构和对比，**不能图文重复**。
4. **可验证表达**：每张图至少回答“它表达的事实是什么、来源在哪、什么还没证实”。
5. **媒介适配**：小屏不是缩小桌面海报；按平台重新组织信息单元。

这些是设计原理与待实测假设，不宣称自动带来完读率/转化率增长。用实际手机预览与发布数据验证。

## 文章母稿：四种文章结构，按题材选一种

| 类型 | 读者诉求 | 建议骨架 | 核心视觉 |
|---|---|---|---|
| 架构解析 | “内部怎样流动？” | 场景→事件→机制→取舍→边界 | 逐状态的系统分镜 |
| 工程实践 | “我能怎么做/怎么证明？” | 失败现场→假设→动作→回执→复盘 | 真实证据图+前后对比 |
| 产品/研究白皮书 | “为什么这么设计？” | 问题定义→设计约束→实现路径→实验条件→局限 | 结构图+可核算数据 |
| 技术资讯/评论 | “有什么变化/影响？” | 可核验事件→直接影响→不同观点→行动建议 | 官方来源卡+一个视觉隐喻 |

章节节奏：**真实场景 → 一个问题 → 一张解释关系的图 → 人话解释 → 证据/反例 → 一句边界**。这不是每节必须执行的死格式；没有信息增量就不做图、没有量化证据就不用图表。

## 图的责任分工与选型

| 类型 | 用途 | 禁忌 | 建议生成 |
|---|---|---|---|
| 封面隐喻 | 引发兴趣、建立品牌识别 | 与文章标题/摘要重复、AI 人物冒充现场 | 原创摄影/几何/可控场景 |
| 概念锚点图 | 一图呈现核心观点 | 试图塞进全文细节 | SVG/HTML→PNG |
| 连续分镜 | 表达状态迁移 | 没有时间/状态变化仍造动画 | 共享底图，多帧静态 PNG |
| 动态图（GIF/视频） | 表达实时变化或渐进路径 | 依赖自动播放才能理解、无静态替代 | 先定分镜与源文件，再按平台导出 |
| 数据图 | 比较实验或记录 | 无分母、条件、来源、伪造中间数据点 | 用可追溯数据生成图表 |
| 官方截图/真实工程截图 | 证据、产品界面、回执 | AI 仿造官方 UI、截屏等同功能实测 | 真实采集并标注来源和许可 |

**规则：静态可读优先**。一张 GIF 的第一帧/封面也须具备基本意义；不确定公众号或目标 App 播放行为时，静态分镜作为正式可阅读内容。不是所有技术图都应动画化。

## 示例：如何把 Super Agent 的概念画成五帧

> **仅作信息设计样例**，不是对具体 DeepSeek 系统的实现声明。细节需逐条回官方仓库与原文校对。

- F0 现场：群聊中的 bug 反馈、没有明确 @；读者理解“为什么需要主动发现”。
- F1 入口：群聊/PR/日程等事件源进入预过滤与意图识别，标清“此处可能被丢弃”。
- F2 决策：Router 对待办事件做批次决策，标清队列、幂等/去重、权限决策和假设。
- F3 执行：Worker 订阅/接手任务，明确执行副作用、上下文引用和失败回退。
- F4 回执：PR/群聊/系统状态回传；标示人工复核、Watchdog 是辅助控制回路，不等于生产可用。
- 配套留两栏：**事实证据**（官方仓库、原文、实验条件）与**未知项**（尚未验证的调用、稳定性、跨平台行为）。此前长图 V1 使用的 6.4s/3.2s/2.1s/1.6s 曲线只可作为“待核验证据位置”的示意，不得当测量数据复用。

## 视觉设计参数（提案口径）

- 品牌色：主色仅 #FFFFFF、#1A1A1A、#F2644F；灰阶 #7A8087/#A8ADB3。原始官方截图可保留其真实品牌色，不强行改色；**不引入蓝/绿作为行途主色**。
- 封面：先遵循 Design PR #2 的极简/低字原则，不强制黑白交替；头条候选 900×383，分享卡等由 Work 实际裁切预览。
- 中文关键文字、代码、数字必须通过 SVG/HTML 可编辑文本层渲染；AI 生成场景图不得承担精确中文文字，不能伪造 UI 与数据。
- 一帧一问题；视觉层次建议“视线焦点/当前节点亮色、已发生灰、未知虚线”，箭头必须能从输入追到输出。
- 说明文案不在图上铺满，图文自然衔接；每张图有替代文本和能独立说明的图注。
- 截图引用与素材字段以 PR #3 为准，至少记录：asset_id、source_url、creator、captured_at、representation、license_or_permission、deid_review、fact_claim、source_sha256、output_sha256、placement、reviewer。

## 一份母稿，多平台分拆

| 渠道 | 输出物与节奏 | 关键约束 |
|---|---|---|
| 微信公众号 | 可检索正文 HTML + 2–5 张**有信息增量时才制作**的图/分镜 + 明确图注；必要时 GIF/视频附静态替代 | 375/414px 真机/模拟预览；确保图片能回读、不靠动图表达唯一信息 |
| 小红书 | 3:4 竖版图卡（已有 Skill 规格参考 1080×1440），一页一观点；建议先试 5–9 页 | 不能把整个长文缩成字密的巨图；封面钩子/后续图卡应有差异 |
| X | 一张主图 + 精简 Thread（现有 Skill 范例 4–5 条）/单条评论附解释链接 | 不自动套公众号标题；英文/中文语境、可点击来源与图片替代文本分别审查 |
| 朋友圈 | 一张易扫读的主图 + 一段真实个人评论，必要时给已公开文章链接 | 无营销口号/未经证实的“实测”声称；不自动发群 |

以上为**设计建议，不覆盖当前平台规则或现有发布时间门禁**。外发时序按 xingtu-skills 当前分发规范及平台最新规则重新确认。

## 一次制作的交付标准

必须同时交：1）结构化内容/论点清单；2）可修改的 SVG/HTML/数据源；3）公众号/小红书/X/朋友圈变体清单；4）实际导出 PNG/GIF/视频（只列已生成文件）；5）素材授权与 SHA 记录；6）手机预览证据；7）未验证事项。
禁止用 AI 生图的视觉完备性代替图片内容的事实校对。
