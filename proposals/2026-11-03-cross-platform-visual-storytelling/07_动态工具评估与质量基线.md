- **xingtu-visual-storytelling**：只负责从事实到设计、能力查找、素材账本及验收的**编排**，不重复实现渲染器。

## 具体改进上一版 GIF 的五点

1. **信息先行**：不要一排框依次发光；必须展示“消息进入→被筛除/进入队列→Router 分叉→Worker 并行→成功/失败回执”中至少一个真实变化，未经核验的机制只标概念示意。
2. **动感来源**：数据 token/消息卡沿连接线传播，决策路径高亮而其他路径退后；箭头线头与节点时序匹配。不要随机漂浮小机器人。
3. **视觉层级**：白/黑/橙红三色，橙红只用于当前状态和关键判断；留白与细腻阴影服务层级，不靠镜面 3D、霓虹和彩色噪声。
4. **节奏**：每次出现的元素应有可读停顿；避免同一时刻多个主角运动，进入与退出用合理的缓动；用首、中、末帧核查遮挡、字距、内容和状态。
5. **对用户友好**：先有可读静态终态，动画不是唯一承载事实的通道；若 GIF 播放性能/颜色损失/文件体积/手机兼容不达标，静态分镜是合格回退。

## 无障碍与微信实际限制

- 参考 [W3C WCAG 2.2 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide)：自动运动如果与正文并行且超过 5 秒，应考虑可暂停/停止；公众号内嵌 GIF 往往没有作者可控的暂停按钮，所以**优先有限循环、简短时长、静态替代**。这是设计参考，不是宣称微信符合认证。
- HTML 中 JavaScript/CSS 的交互不能被视为微信图文能直接运行的机制，必须**实际导出媒介**并由发文通道回查。
- GIF 压缩会损失色彩、细线与字体；应从可编辑源导出，再看首、中、末三帧+动图循环点+中文字；存在图片 CDN 转换就再回读验证。
- 真实例子：既有 [vault PR #18](https://github.com/xingtu1996/xingtu-vault/pull/18) 的 v5 私人草稿据 PR 记录已回读 GIF 媒体，但手机微信**持续播放**仍待用户审核，不等于本次已验证平台兼容。
