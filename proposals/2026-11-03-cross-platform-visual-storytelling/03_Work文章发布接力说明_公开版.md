## 二、接力工作清单（先发现已有动作，再执行）

**阶段 0｜对账**
- 先定位 Work 当前既有“发布文章”动作：对应文章标题、母稿版本、发布包路径/manifest/SHA、计划渠道、最新人工审稿意见、当前草稿箱实际状态；未知写“待核”，不凭旧聊天推定。
- 避免与其他 Work/Muse/本地 Codex 并行写同一发布包。要有原子版本号、修改记录、预先确定接力所有者。**若当前任务是 PR #18，已存在一份私人草稿，应优先只读核查并做设计差异建议，不再盲目 draft/add，也不覆盖已审 v3。**
- 对齐项目仓：设计规范源 = xingtu-design；私有生产包 = xingtu-vault；执行能力 = xingtu-skills；真实发布状态以平台回查为准。公开设计仓绝不落私有客户/账户信息。

**阶段 1｜事实与视觉分镜**
- 以实际文章最终事实清单，生成视觉结构单（`claim_id → source_url/证据 → visual_type → frame_id → caption → permission`）。
- 优先解释“一个状态如何变成下一个状态”；公众号保留完整可复制 HTML；小红书 3:4 图卡、X Thread/单图、朋友圈单图均由同一事实源做**结构级改写**。
- 假数据、未经证实图表、研究原型被称为生产系统、AI 图冒充真截图 → 阻断。
- 先校准用户会话中 Super Agent 长图 V1 的问题：图中文字与来源二次核对；其中示例折线图不得当实验事实；结构、术语与真实原型须核对官方资料。

**阶段 2｜技能路由与制作**
- 核对技能版本、路径、运行权限（不是仅看 README 声称 find-skills 可检索）。
- 有可用静态流程工具，先产 4–5 张连贯分镜 PNG 和可修改源；需要且实测可用时再增产 GIF/视频。保留静态降级版本。
- 对官方截图按 PR #3 采集/许可/脱敏/图注；第三方公众号截图只作研究参考，未获复用许可不嵌入新稿。
- 不复制外部作者的整套图表样式，归纳通用叙事手法即可。

**阶段 3｜包体与发布门禁**
- 产出：最终正文 MD、公众号 HTML、封面文件、逐张配图及源、图注、manifest（含来源/授权/哈希/图→论点映射）、渠道变体、移动预览、README 操作单、差异记录。
- 实际视觉验收：900×383 封面裁切；375/414px 正文预览；小红书 1080×1440 图卡；X/朋友圈小屏裁切。检查字体、换行、过密、中文错字、SVG/GIF 的移动端回退。
- 运行隐私/版权/事实/规范漂移核查；用实际脚本日志+exit code+hash 回报 PASS/FAIL/NOT_RUN，不能凭“看过设计稿”放行。
- 如果旧技能强制黑白交替、配图数量、旧红色，请明确记录“旧运行时规范 vs Design v1 提案冲突”，先以当前允许操作的版本做安全生产，不擅自全局改写技能或镜像。

**阶段 4｜草稿箱和对外发布**
- 公众号**仅在已获得当前任务的明确授权**且所有发布门禁通过时，可按现有 SOP 创建/更新私人草稿；`draft/get` 回查标题、摘要、图片与 HTML 版本。对于已经建稿的 PR #18，应优先复核**已存在**草稿，任何改稿/覆盖须经过当前任务的专门审稿决定与版本对账；无授权则止于可审核包。
- 上传到 GitHub ≠ 微信草稿箱创建 ≠ 已公开发布。不得自动群发、发表、跨平台推送、朋友圈转发。
- 小红书/X/朋友圈优先只生成可供人工审核和操作的素材；发布/排期另走其平台时序与人工确认。

按「结论→证据→风险→建议动作」，提供：
1. 真实处理的是哪一篇文章（标题、repo、PR、包路径、版本 SHA）；是否复用了既有发布动作。
2. 制作了哪些文件，放在何处，每个图的用途、来源和状态；是否含 GIF/MP4，实测情况。
3. 哪些自动化检查通过、哪些 NOT_RUN、关键失败与阻断。
4. 微信草稿箱是否真实创建/更新（若有，提供私有回执与回读证据，不在公共设计仓泄露 ID/凭据）。
