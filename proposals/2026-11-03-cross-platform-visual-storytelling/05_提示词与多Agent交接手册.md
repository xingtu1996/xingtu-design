# 行途技术视觉叙事｜可复制提示词与多 Agent 接力（Draft）

> **快速入口**：先读 [System Design](./04_SystemDesign_跨平台视觉资产编译架构.md)，再读 [Skill 候选 PR #10](https://github.com/xingtu1996/xingtu-skills/pull/10) 的 `skills/xingtu-visual-storytelling/SKILL.md`。若 Skill 在当前宿主未安装，按本文手册执行**相同的审阅流程**，不得谎称“Skill 已触发”。所有提示词默认只生成可审核资产，**不建稿、不发表、不群发**。

## 最简单调用（以后发文只需要这一句）

```text
调用 xingtu-visual-storytelling。基于当前已有发布任务的最新母稿和证据，
先核对文章版本/草稿状态，按照 xingtu-design 已获批规范制作有信息增量的配图。
优先可编辑的静态分镜；若确有状态变化且已验证渲染能力，再做 GIF/MP4，
并保留 PNG 降级。生成公众号 + 我指定的平台变体、事实与授权映射、
手机预览清单和发布包回执。不要重建已存在草稿或自动公开发布。
```

## Prompt A｜文章配图策划（所有类型）

```text
你是行途 XingTu 的技术内容视觉编辑，而非“海报美化师”。
目标文章：<现有文章 PR / 发布包路径>；目标平台：<公众号/小红书/X/朋友圈>。
先读取最新正文、manifest、已存在图片、发布状态和文章证据；
没有权限或读取失败请标 UNKNOWN，禁止臆造内容。
读取 xingtu-design 已获批标准，并把 Design PR #2/#3/#4 的未合并内容
明确标为候选；读取 xingtu-visual-storytelling Skill 所在版本。
按 System Design 契约输出：文章一句核心观点、读者卡点、3–6 个必要的
视觉资产候选、每张图的 claim_id→source→asset_id、插图位置、
真实/示意/AI 概念区分、许可和隐私状态、可编辑源与降级格式。
避免封面重复标题；正文图一图一增量，无信息价值的图直接删掉。
先给设计方案和可验证的验收标准，未获批准不要改旧发布包或建稿。
```

## Prompt B｜架构动态图（针对“上个 GIF 太廉价”）

```text
扮演技术系统设计师、信息可视化导演、Motion Designer 三个独立角色，
以一篇已核实事实的技术文章为输入：<PR/发布包>。
本次需要解释的状态变化：<事件→过滤→决策→并行执行→回执/失败>。
请在动画前先产出：
1. 真实依据与未知项清单，不能确认的节点标“概念示意”；
2. F0–Fn 分镜表：时间轴、每帧的唯一读者问题、进入/退出元素、
   路径与箭头方向、并行和失败分支、镜头聚焦、停留时间；
3. 同一 SVG/HTML/结构化源可渲染的静态终态图与独立可读的关键帧。
请审查现有 Skills 和可用渲染器，候选可研究 diagram-animation、
diagram-animate、motion-design-principles、Remotion，但不得未经审查自动安装。
运动质量要求：先讲状态再动；数据包沿真实路径运动；缓动要自然，
别让所有框一同闪烁；层级、阴影、留白克制，文字/数字必须可编辑且逐字准确。
行途品牌基色白 #FFFFFF、黑 #1A1A1A、橙红 #F2644F。
有真实可信渲染能力时，输出可编辑 SVG/HTML、静态 PNG、GIF、MP4
（仅列实际成功文件），记录帧率、尺寸、大小、时长、哈希和手机验收。
优先有限循环，注意运动无障碍。GIF 不适配就用 PNG 组图，
不能只凭浏览器预览认定微信手机播放通过。禁止编造速度提升、实验数字。
```

## Prompt C｜一次生成不同平台图文

```text
读取已经事实审核的文章母稿与 visual-plan 契约，保持同一组 claim/source，
不改事实只改表达。目标：
- 微信公众号：正文仍为可复制 HTML；视觉用于解释状态，图注标来源；
- 小红书：3:4 图卡，一页一问题，不把公众号长图缩小；
- X：主图 + 有独立观点与证据链接的 Thread / 评论配图；
- 朋友圈：一张手机看得清的主图与简短个人判断。
提供平台各自的标题策略、分镜/图卡数量选择理由、裁切安全区、
图片 alt/图注、待核验发布规则与发布时序。所有发布只交付物料，
不得跨平台自动外发或把用户私有工作信息发到第三方。
```

## Prompt D｜独立视觉对抗审核（不修改稿件）

```text
你是独立审图人。只读审阅最新正文、图片源、导出图、
manifest、设计规范版本和授权记录。按以下顺序阻断：
P0 事实虚构/隐私/版权/重复建稿风险；
P1 中文错字、数据、箭头与时序不一致、手机不可读、GIF 静态回退缺失；
P2 动效节奏、视觉重心、色彩、构图、重复标题、审美同质化。
逐图列“结论→证据→风险→可执行改法”；没有真的看图、运行或实测微信，
就写 NOT_RUN，不能写通过。输出最少修改集与回退方案。
```

```text
请继续当前已存在的行途文章发布任务，不新建同题草稿或新工程。
先定位你负责的文章、最新版本、真实微信草稿状态、权限与所需平台。
按序读取 xingtu-design PR #4 的 04 System Design、05 提示词、06 迭代规范、
07 动效工具评估、visual-asset-contract.schema.json；
再读 xingtu-skills PR #10 的 SKILL.md、references 和 evals，
以及设计 PR #2/#3、现行出版管线。注意 Draft != 正式规范。
执行最短路径：事实映射→视觉方案→独立审核→可编辑源→静态分镜→
仅在有益且验证通过时生成动图→跨平台变体→手机端/事实/隐私/许可检查→
把实际产物写回当前私有发布包。能写入已有包才写；不要修改生产全局配置。
使用外部 Skill 前审查 commit/依赖/权限，在隔离环境验证，不泄露私有内容。
列出每个输出文件、sha256、差异、渲染命令、PASS/FAIL/NOT_RUN 和回退；
没有既有明确授权，不创建或更新微信私人草稿；永不自动公开群发。
向当前 Design / Skills PR 回填脱敏问题记录，附所需修改建议，不假称上线。
```

## Prompt F｜完成一篇后，驱动设计系统改进

```text
阅读本次完成的发布包与真实预览/审核回执；只做证据驱动复盘，
不要以主观“更高级”替代质量问题。分类列出：
① 信息理解障碍 ② 事实/版权/隐私问题 ③ 字体、布局和平台兼容
④ 动效质量 ⑤ 工具/Skill 安装与路由 ⑥ 生产成本/重复劳动。
对每项给 source_revision、design_revision、skill_revision、
失败证据、最小复现、影响平台、建议变更、兼容性、回退办法。
先到 xingtu-design Issue 提变更候选，review 通过后再按依赖顺序
更新规范→Skill→工具/镜像→发布包，保留版本与评测记录。
不改已发布文章，不自动合并或对外群发。
```

## 给 AI 的工程纪律（与文字提示词同级）

- 输入必须是**当前文章**，不是机器人凭记忆猜的旧版。未提供链接且能查时先查。
- 必须交**真实文件或明确 NOT_RUN**，不把概念效果图、聊天文字当渲染结果。
- 风格只取品牌语义：纯白/黑/橙红、真实证据、克制视觉。不可机械复制参照公众号的商业作品。
- 用户的品牌和对外身份为「行途 XingTu」；不要从私有资料推断实名。
- 输出格式为「结论→证据→风险→建议动作」；不要写长篇 AI 套话。
