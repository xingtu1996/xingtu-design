# 官方截图采集与使用规范（拟议，配合 Design v1 提案）

适用范围：行途技术手记及后续内容产品在评测、案例、教程类文章中引用第三方官方页面截图时使用。本文件只含可公开复用的方法与字段，不含任何私有文章正文、账号信息或发布日志。

## 一、基本原则

1. **真实采集**：截图必须来自真实浏览器对官方页面的实际访问。禁止用 AI 生成、手工仿制或拼接的方式伪造产品界面、文档页面或后台画面。
2. **证据边界**：官方文档截图只证明「官方文档在采集时有此说明」，不等于行途已实测该功能。图注与正文不得把文档截图表述为运行测试结果。
3. **原始与编辑分离**：原始截图原样归档、永不覆盖；裁切、压缩、标注另存为编辑图。任何一步处理都不得改变原文含义（不得删改文字、不得移动元素位置、不得合成不存在的内容）。
4. **最少够用**：正文截图按信息增量选取，一般 2–4 张；不为凑图堆叠同类页面。真实证据优先，概念图只做辅助解释，两者在图注中明确区分。

## 二、采集要求

- 来源只限官方域名（厂商文档站、官方仓库、官方帮助中心）；聚合站、媒体转述页不作截图来源。
- 优先截取能证明具体论点的**局部正文**（一个小节、一段规则、一处权限说明），避免整页长图直接进正文。
- 采集环境记录浏览器与版本、页面语言、登录状态（公开页应未登录采集；如页面需登录，须在记录中注明且截图不得含个人账号信息）。
- 页面含个人信息、内部数据或第三方隐私时，先脱敏评估；不能脱敏的页面不截图、不用图。
- 页面访问失败时记录失败原因与时间，不伪造成功，不拿旧图冒充本次采集。

## 三、标准记录字段（每张图必填）

沿用本提案 `01_三类封面与排版样板.md` 的素材记录字段：

`asset_id, source_url, creator, captured_at, representation, license_or_permission, deid_review, fact_claim, source_sha256, output_sha256, placement, reviewer`

补充约定：

- `asset_id`：`SHOT-<厂商>-<序号>`，如 `SHOT-CNB-01`。
- `captured_at`：UTC 与北京时间双记。
- `representation`：官方截图统一标 `official_screenshot`；与 `concept_diagram`（原创概念图）、`ai_generated`（AI 生成图）严格区分。
- `license_or_permission`：三态——`editorial_reference`（编辑引用，附来源与日期）/ `licensed`（有明确授权）/ `pending_review`（待审，不得发布）。官方文档与仓库页面多为编辑引用：须附来源链接与采集日期，不暗示获得厂商背书。
- `fact_claim`：这张图支撑的正文论点，一句话写清；写不出论点的图不进正文。
- `placement`：正文插入位置（章节 + 前后段落锚点）与图注全文。
- `source_sha256` / `output_sha256`：原图与编辑图分别计算，任一文件被替换必须重新计算并更新记录。

## 四、编辑规则

- 允许：等比缩放、裁切无关区域、压缩体积、在图外加来源条。
- 允许但须披露：在图上加框选/箭头标注时，图注注明「红框为行途标注」；标注色只用品牌橙红 `#F2644F`。
- 禁止：修改页面文字、增删界面元素、把不同页面拼成一张「截图」、用编辑图冒充原图归档。
- 微信正文图宽度按 100% 展示，编辑图宽度建议 ≥1080px，单张体积以平台可上传且加载流畅为准（经验值 ≤1MB，超限先压缩再裁切）。

## 五、图注标准

格式：`图N：<一句话说明图里是什么、证明什么>。来源：<官方页面名>，<采集日期> 截图。`

- 图注必须含来源与采集日期；概念图、AI 图用各自的既有标注口径，不与截图混用。
- 不重复文章标题，不在图注里下截图本身证明不了的结论。

## 六、发布前检查（逐项打勾）

- [ ] 每张截图都有完整记录字段，原图与编辑图哈希可回读一致。
- [ ] 图注与正文论点对应，无过度声称（文档截图未写成实测）。
- [ ] 许可状态非 `pending_review`；来源链接在发布当日可打开。
- [ ] 截图中无个人信息、凭据、内部路径。
- [ ] 手机端 375/414px 预览下文字可辨、裁切不挡关键内容。
- [ ] 失败或未采集的条目在执行记录中如实标注，不 silent 省略。

## 七、示例（公开信息）

技术产品评测类文章引用官方文档截图的典型组合：上游开源仓库 README 的定位声明（证明产品边界）、官方文档的权限模型段落（证明授权机制）、官方帮助中心的协作方式说明（证明团队用法）。具体文章与发布包保存在私有仓，不在本仓展开。
